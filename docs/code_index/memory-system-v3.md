# Code Index: Memory System (v3)

Feature doc: [memory-system-v3.md](../features/memory-system-v3.md). The legacy associative layer (events/edges/FTS/rules) has been retired; recall is cosine-only over an embedded claim store, with keyed markdown entity profiles and an offline LLM consolidation engine.

## Source files

### Core store
- `src/memory/types.ts` — Public types: `MemorySourceRecord`; v3 `ClaimInput` (incl. `skipDedup`)/`ClaimWriteResult`/`ClaimRecallOptions`/`ClaimRecallResult`/`ClaimVectorExport`; `EpisodeInput`; decay types (`ArchiveStaleClaimsOptions`, `CollapseDuplicateClaimsOptions`, `MemoryHealth`); consolidation read options (`UnconsolidatedSourceRecordOptions`). Also the legacy `MemoryLessonInput`/`MemoryFactInput` still used by `add-lesson`/`add-fact`.
- `src/memory/store.ts` — `MemoryStore` interface (the provider boundary): `appendSourceRecord`, `upsertLesson`/`upsertFact`, `upsertClaim`, `appendEpisode`, `listUnconsolidatedSourceRecords`, `markSourceRecordsConsolidated`, `recallClaims`, `appendRecallLog`, `exportClaimVectors`, `markEpisodesUsed`, `markClaimsUsed`, `archiveStaleClaims`, `collapseDuplicateClaims`, `memoryHealth`.
- `src/memory/sqlite.ts` — `SqliteMemoryStore` (the only impl). Owns the schema (`memory_source_record`, `memory_node`, `claim`, `episode`, `recall_log`, plus retained tag/provenance tables); `claim.retrieval_text` is the rebuildable document projection while `claim.text` remains authoritative; `recallClaims` does SQL `WHERE` pre-filter then **brute-force cosine in TS**, ordered by raw semantic relevance (weight is metadata and the vector-less fallback), bumping `last_used_at` unless `recordUsage:false`; `markClaimsUsed(ids, now)` is the deferred bump for callers that retrieve candidates first and only later know which ones reached a prompt (pre-recall synthesis); `archiveStaleClaims` archives stale **and** low-value claims (`active=0`, never deletes); `memoryHealth` reports per-kind corpus/never-used/fade-candidate counts **plus the near-duplicate rate** (all-pairs cosine per dedup scope, rate measured over the EMBEDDED claims of the kind — vector-less legacy rows can never be twins and would dilute it; `includeNearDuplicates:false` skips the scan, which is synchronous and O(n²), so keep it off any request path). Float32-LE BLOB (de)serialization + `cosineSim` helpers live here. `ensureMemoryNodeAllowsClaim` retrofits the `kind` CHECK on pre-v3 DBs.
  - **`upsertClaim` is THE claim write chokepoint** ([claim-dedup-write-guard.md](../features/claim-dedup-write-guard.md)). It (a) rejects an insert with no `embedding`, (b) scans active claims in the same dedup scope (`private findNearDuplicate`: same `kind`, `repo IS ?`, self excluded) and MERGES into the deterministic winner — bumping `helpful_count`/`weight` (`CLAIM_MERGE_WEIGHT_BUMP`, clamped at `CLAIM_MERGE_WEIGHT_CEILING`) and refreshing `last_used_at` — instead of writing a twin, and (c) patches value/vector columns with `COALESCE(<raw bind>, claim.col)` so an omitted field no longer erases stored weight, counters, `last_used_at`, or the embedding. Scan + write share ONE **IMMEDIATE** transaction (read-then-write under WAL; deferred would die on the non-retryable `SQLITE_BUSY_SNAPSHOT`, which `PRAGMA busy_timeout = 5000` cannot rescue — and that pragma is per-CONNECTION, so handles opened by `migrate-v3.ts` / the routing-log migration do not inherit it). Returns `ClaimWriteResult` (`inserted` | `updated` | `merged`). Re-scans on insert, on a text change, and on a re-add of an archived row. `skipDedup` waives (a) and (b) for verbatim restore writes — but never the COALESCE patching.
    - When the merging write is an **UPDATE of a still-active row**, that row is folded into the survivor (counters in, `active = 0`) with `collapseDuplicateClaims` semantics, so the text the caller just superseded stops competing in recall. An already-archived row is NOT re-folded (the sweep banked its counters once), which keeps repeated re-adds idempotent. The merge bump is clamped so N repeated identical merges converge at `CLAIM_MERGE_WEIGHT_CEILING = 2.0` instead of climbing +0.1 forever past every other claim's `cosine * weight`; the clamp never lowers an explicitly-set higher weight. **The clamp is the only bound that exists**: no code path decrements a claim's `weight`, and `archiveStaleClaims` has no production caller (definition + interface + one test only), so an over-weighted claim never fades. See the cut-list entry in [claim-dedup-write-guard.md](../features/claim-dedup-write-guard.md).
  - `collapseDuplicateClaims` is the sweep's write primitive: sum the duplicates' counters into the survivor, inherit the cluster's newest `last_used_at` (never "now" — a backfill must not invent freshness), archive the rest.
- `src/memory/dedup.ts` — Shared dedup policy so the guard, the consolidation engine, and the sweep judge "same claim" identically: `DEFAULT_DEDUP_THRESHOLD` (0.92), `resolveDedupThreshold()` (`MEMORY_DEDUP_THRESHOLD`, falls back on a bad value), `compareDedupWinner` (highest `weight` → oldest `created_at` → lowest `id`), `dedupScopeKey(kind, repo)`. Known gap noted in the module header: the cosine function itself is still forked between `sqlite.ts` (`cosineSim`) and `consolidate.ts` (`cosine`).
- `src/memory/dedup-sweep.ts` — `runDedupSweep`: offline backfill for near-duplicates that predate the guard. Groups `exportClaimVectors()` by dedup scope, greedy single-link clusters each scope (members pre-sorted by `compareDedupWinner`, so the survivor matches what the guard would pick), and — **only with `apply: true`** — calls `collapseDuplicateClaims`. Dry run by default, like `migrate-v3.ts`. `formatDedupSweep` renders the Slack/CLI summary.
- `src/memory/factory.ts` — `createMemoryStore(dbPath = "data/memory.db", options?)` → `SqliteMemoryStore`; `options.dedupThreshold` comes from `config.memory.dedupThreshold` at boot, else `MEMORY_DEDUP_THRESHOLD`.
- `src/memory/ingestion.ts` — `MemoryIngestor`: hot-path capture. `captureSlackMessage` / `captureRunnerResult` / `captureRoutingDecision` / `captureRunnerEvents` write **only** `appendSourceRecord` (raw provenance — not recallable). Plus `sourceIdFor`/`slug` helpers.
- `src/memory/cli.ts` — `runMemoryCli`: commands `consolidate-v3` (runs `runConsolidationSweep`), `recall-claims` (`--query` embeds in-process; inspection — `recordUsage:false`), `add-claim` (embeds via the provider when `--embedding` is omitted; `--skip-dedup` is the verbatim hatch), `add-lesson`, `add-fact` (the `add-*` commands **mirror** into the claim store via `mirrorClaim` so new lessons/facts are immediately recallable; the mirror reports `claimAction`/`claimId` so a merge is visible), and `dedup-sweep [--threshold n] [--apply]` (dry run without `--apply`).
- `src/memory/retrieval-text.ts` — deterministic lesson/fact retrieval projections; lesson projections include `applies_when`.
- `src/memory/reembed-retrieval.ts` — recoverable corpus backfill (`bun run memory:reembed`): exports JSONL, optionally rewrites projections in validated Cursor Composer batches, dry-runs by default, creates an SQLite backup before `--apply`, then locally re-embeds every active claim without changing authoritative text.
- `src/memory/migrate-v3.ts` — One-shot, committed, dry-run-by-default migration: legacy `lesson`+`memory_fact` → embedded `claim` (proximity-dedup), then `dropCondemned`-gated DROP of `memory_event`/`edge`/`mention`/`memory_search_doc`/`candidate_rule`/`memory_fts`. Cutover is complete. Writes with `skipDedup: true` — it has already clustered, and historical rows (including archived ones) must go in verbatim.

### Embeddings (`src/memory/embedding/`)
- `local.ts` — `LocalEmbeddingProvider`: in-process `onnx-community/harrier-oss-v1-270m-ONNX` (640-dim, q8) via `@huggingface/transformers`. Last-token pooling (reads the model's `sentence_embedding` output), query-vs-document prompt templates, one text per forward pass (no padded batches).
- `hashing.ts` — `HashingEmbeddingProvider`: deterministic zero-dependency stub for tests/dev.
- `factory.ts` — `createEmbeddingProvider("local" | "hashing")`.
- `types.ts` — `EmbeddingProvider` / `EmbedMode` ("query" | "document").

### Profiles (`src/memory/profiles/`) — keyed, markdown, not embedded
- `store.ts` — `ProfileStore`: files at `<root>/<people|repos|situations>/<slug>.md`; `upsertProfile` (keyed merge by `entity_ref`, unions evidence, bumps `updated_at`), `fetchByEntityRef` (single keyed read; bumps `last_used_at` only when `recordUsage:true`), `list`. Profile↔markdown mapping + field specs per kind.
- `types.ts` — `ProfileKind` (person/repo/situation), `Profile`/`ProfileBase`/`ProfileInput`, `ProfileFetchOptions`.
- `frontmatter.ts` — `parseDocument`/`serializeDocument` (frontmatter + prose body).
- `factory.ts` — `createProfileStore`. `index.ts` — barrel.

### Consolidation engine (`src/memory/consolidation/`) — offline LLM write path
- `consolidate.ts` — `consolidateSession`: uses a pre-fetched `records` set when given (else reads unconsolidated records by `threadId`/`limit`), builds context (existing profiles — keyed refs first, then the rest of the corpus via `ProfileStore.list()` newest-first up to `PROFILE_CONTEXT_CAP = 20` — plus nearby claims and the resolved identity map from optional `resolvePeople`), calls the injected LLM (forwarding `bodyCap` to the prompt), persists **episodes → profiles → claims** (cosine proximity-dedup at `DEFAULT_DEDUP_THRESHOLD = 0.92`, bucketed by `dedupScopeKey` for both the existing-claim pre-check and the in-batch check — an unscoped pre-check DROPS a repo-scoped draft that merely sits near a global claim, and a drop is strictly worse than the store's merge), stamps records consolidated. Local `cosine` + `fnv1a` (stable 64-bit claim id) helpers.
- `identity.ts` — `referencedSlackUserIds` (batch's `actor_id`s + `<@U…>` mentions), `PeopleResolver` (id → display name; unresolved ids omitted), `createSlackPeopleResolver` (production: `users.info` via the shared `resolveUserName` cache). Evidence names people only as raw Slack ids, so without this the model can't attribute anything to a person profile.
- `sweep.ts` — `runConsolidationSweep`: the shared orchestration loop. Full-sweep mode fetches all unconsolidated records once, FILTERS to allowed `kinds` (`DEFAULT_CONSOLIDATION_KINDS` = `slack_message`/`curated_fact`/`manual_correction`; excluded kinds like `runner_output`/`routing_decision` are deferred, never marked), groups by thread (unthreaded → `(unthreaded)`), SPLITS any group whose body-capped size exceeds `maxBatchChars` into consecutive ≤budget sub-chunks (`splitGroup`; a lone over-budget record is its own chunk), then First-Fit-Decreasing bin-packs the remaining groups by body-capped char total (`DEFAULT_MAX_BATCH_CHARS` 48000, `DEFAULT_BODY_CAP` 2000) so several threads share one runner call; threads stay contiguous, each batch is isolated on failure. `threadId` mode keeps the single-thread `limit` path (no kind filter). Entries carry `threadIds: string[]`. `summarizeConsolidationSweep` for human output. Used by the CLI, the workflow, and the MCP tool.
- `runner.ts` — `createRunnerInvoke`: production `ConsolidationInvoke`. `runner: "claude" | "opencode" | "codex"` (default `opencode`) selects the one-shot subprocess (injectable `runText`): `opencode run --model <m> --format json "<prompt>"` (`openCodeRunText`); `claude -p … --output-format json` (`defaultRunText`); or `codex exec` (`codexRunText` + `buildCodexConsolidationArgs`) fully isolated (`--ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -s read-only --color never`), run from a neutral cwd (`os.tmpdir()`) with the prompt on **stdin** and the final message read from a unique `-o` temp file (deleted after) — isolation is required or junior's Stop/learnings hooks hijack the output. The model is ALWAYS pinned — `DEFAULT_OPENCODE_MODEL = opencode-go/deepseek-v4-pro`, `DEFAULT_CLAUDE_MODEL = claude-opus-5` (a VALID id; `sanitizeClaudeModel` defensively strips a trailing `[…]` tag like junior's `[1M]` notation), `DEFAULT_CODEX_MODEL = gpt-5.6-sol` with `effort` default `medium` (`-c model_reasoning_effort="…"`). Output is parsed/validated against `consolidationOutputSchema`; 5-min timeout guard SIGINTs the process tree.
- `prompt.ts` — `buildConsolidationPrompt(records, context, bodyCap?)`: encodes the HIGH BAR (default output is empty) + shows existing profiles/claims to avoid restating (profile bodies near-whole, 1500-char guard, because an emitted body REPLACES the file's) and a "Who is who" Slack-id → name section (from `context.people`; `from=` lines are name-annotated; reuse a shown profile's exact `entity_ref`, never a second slug); notes records may span multiple `thread=` groups (judge each on its own). With `bodyCap` set it truncates ONLY `BODY_CAPPED_KINDS` (`runner_output`/`routing_decision`) bodies (`…[truncated]`); high-value kinds go in whole. `cappedBodyLength()` is the shared sizing helper the sweep uses so packing matches what is sent.
- `types.ts` — `EpisodeDraft`/`ProfileDraft`/`ClaimDraft`, `ConsolidationOutput`/`ConsolidationInvoke`, `ConsolidationReport`, and `consolidationOutputSchema` (JSON Schema). `index.ts` — barrel.

## Integration points (outside `src/memory/`)
- `src/index.ts` — builds the store + `MemoryIngestor` on boot, injects the ingestor into the session manager.
- `src/session/manager.ts` — hot path: `captureSlackMessage` on incoming messages, `captureRunnerResult` on runner completion.
- `src/mcp/slack-server.ts` — MCP tools `memory_recall` (`recallMemory`: keyed profiles + relevance-first cosine recall, default 0.55 floor, final-result usage accounting and recall logging, fact-subtype filters, preserved `factKind`, optional procedure quota), `memory_add` (`addMemory`: embed + store one claim; returns the store's `ClaimWriteResult`, so the caller can tell "stored" from "already knew that"), `memory_consolidate` (`runConsolidationSweep`). Lazy embedder/profile-store seams; `withMemoryStore` opens/closes per call.
- `src/workflows/executor.ts` — the `memory-consolidation` workflow runs `runConsolidationSweep` (sweep IS the LLM pass); the `memory-dedup-sweep` workflow runs `runDedupSweep` natively in REPORT-ONLY mode (deterministic, so no runner; applying stays an explicit operator CLI action).
- `src/config.ts` — `config.memory.dedupThreshold` (`MEMORY_DEDUP_THRESHOLD`, default 0.92), passed into the store at boot from `src/index.ts`.
- `src/http/routes/memory.ts` — dashboard: `handleMemoryRecall` (embeds query at the boundary, `recordUsage:false`), `handleMemoryProjection` (`exportClaimVectors` → `projectClaims`), plus `/api/memory` docs browsing.
- `src/http/projection.ts` — `projectClaims`: PCA-to-2D + KNN edges for the "memory cloud" debug view (computed at render time, nothing stored).

- Fixtures that need a vector-less or deliberately near-identical claim row seed it with `skipDedup: true` — that flag is the only way past the write guard, and using it marks the fixture as synthetic rather than a production write path.
