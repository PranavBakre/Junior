# Code Index: Memory System (v3)

Feature doc: [memory-system-v3.md](../features/memory-system-v3.md). The legacy associative layer (events/edges/FTS/rules) has been retired; claims use hybrid vector + exact-token recall over one SQLite source of truth, with keyed markdown entity profiles and an offline LLM consolidation engine.

## Source files

### Core store
- `src/memory/types.ts` — Public types: `MemorySourceRecord`; v3 `ClaimInput` (incl. `skipDedup`)/`ClaimWriteResult`/`ClaimFeedbackResult`/`ClaimRecallOptions` (incl. optional raw-channel eligibility floors)/`ClaimRecallResult`/`ClaimVectorExport`; source-context size limits; `EpisodeInput`; decay types (`ArchiveStaleClaimsOptions`, `CollapseDuplicateClaimsOptions`, `MemoryHealth`); consolidation read options (`UnconsolidatedSourceRecordOptions`). Also the legacy `MemoryLessonInput`/`MemoryFactInput` still used by `add-lesson`/`add-fact`.
- `src/memory/store.ts` — `MemoryStore` interface (the provider boundary): `appendSourceRecord`, rolling-history `listSourceRecords`, `upsertLesson`/`upsertFact`, `upsertClaim`, `appendEpisode`, `listUnconsolidatedSourceRecords`, `markSourceRecordsConsolidated`, `recallClaims`, `appendRecallLog`, `exportClaimVectors`, `markEpisodesUsed`, `markClaimsUsed`, `recordClaimFeedback`, `archiveStaleClaims`, `collapseDuplicateClaims`, `memoryHealth`.
- `src/memory/sqlite.ts` — `SqliteMemoryStore` (the only impl). Owns the schema (`memory_source_record`, `memory_node`, `claim`, `episode`, `recall_log`, plus retained tag/provenance tables); `claim.text` remains authoritative while optional bounded `source_path`/`source_heading`/`source_text` retain parent context. Replacing authoritative text clears omitted old source fields; idempotent same-text writes still preserve them. `recallClaims` applies the SQL `WHERE` pre-filter, independently ranks cosine and exact-token coverage in TS, and uses normalized reciprocal-rank fusion only for an explicit exact-anchor query. Optional raw-channel eligibility floors are applied before `limit`, so fused but irrelevant rows cannot crowd out eligible hits. Raw channel scores remain available for diagnostics. It bumps `last_used_at` unless `recordUsage:false`; `markClaimsUsed(ids, now)` is the deferred bump for callers that retrieve candidates first and only later know which ones reached a prompt (pre-recall synthesis). `recordClaimFeedback(ids, useful)` atomically increments `helpful_count` or `unhelpful_count` and returns updated counters for known ids. `archiveStaleClaims` archives stale **and** low-value claims (`active=0`, never deletes); `memoryHealth` reports per-kind corpus/never-used/fade-candidate counts plus the near-duplicate rate. Float32-LE BLOB (de)serialization + `cosineSim` helpers live here.
  - **`upsertClaim` is THE claim write chokepoint** ([claim-dedup-write-guard.md](../features/claim-dedup-write-guard.md)). It (a) rejects an insert with no `embedding`, (b) scans active claims in the same dedup scope (`private findNearDuplicate`: same `kind`, `repo IS ?`, self excluded) and MERGES into the deterministic winner — bumping `helpful_count`/`weight` (`CLAIM_MERGE_WEIGHT_BUMP`, clamped at `CLAIM_MERGE_WEIGHT_CEILING`) and refreshing `last_used_at` — instead of writing a twin, and (c) patches value/vector columns with `COALESCE(<raw bind>, claim.col)` so an omitted field no longer erases stored weight, counters, `last_used_at`, or the embedding. Scan + write share ONE **IMMEDIATE** transaction (read-then-write under WAL; deferred would die on the non-retryable `SQLITE_BUSY_SNAPSHOT`, which `PRAGMA busy_timeout = 5000` cannot rescue — and that pragma is per-CONNECTION, so handles opened by `migrate-v3.ts` / the routing-log migration do not inherit it). Returns `ClaimWriteResult` (`inserted` | `updated` | `merged`). Re-scans on insert, on a text change, and on a re-add of an archived row. `skipDedup` waives (a) and (b) for verbatim restore writes — but never the COALESCE patching.
    - When the merging write is an **UPDATE of a still-active row**, that row is folded into the survivor (counters in, `active = 0`) with `collapseDuplicateClaims` semantics, so the text the caller just superseded stops competing in recall. An already-archived row is NOT re-folded (the sweep banked its counters once), which keeps repeated re-adds idempotent. The merge bump is clamped so N repeated identical merges converge at `CLAIM_MERGE_WEIGHT_CEILING = 2.0` instead of climbing +0.1 forever past every other claim's `cosine * weight`; the clamp never lowers an explicitly-set higher weight. **The clamp is the only bound that exists**: no code path decrements a claim's `weight`, and `archiveStaleClaims` has no production caller (definition + interface + one test only), so an over-weighted claim never fades. See the cut-list entry in [claim-dedup-write-guard.md](../features/claim-dedup-write-guard.md).
  - `collapseDuplicateClaims` is the sweep's write primitive: sum the duplicates' counters into the survivor, inherit the cluster's newest `last_used_at` (never "now" — a backfill must not invent freshness), archive the rest.
- `src/memory/dedup.ts` — Shared dedup policy so the guard, the consolidation engine, and the sweep judge "same claim" identically: `DEFAULT_DEDUP_THRESHOLD` (0.92), `resolveDedupThreshold()` (`MEMORY_DEDUP_THRESHOLD`, falls back on a bad value), `compareDedupWinner` (highest `weight` → oldest `created_at` → lowest `id`), `dedupScopeKey(kind, repo)`. Known gap noted in the module header: the cosine function itself is still forked between `sqlite.ts` (`cosineSim`) and `consolidate.ts` (`cosine`).
- `src/memory/dedup-sweep.ts` — `runDedupSweep`: offline backfill for near-duplicates that predate the guard. Groups `exportClaimVectors()` by dedup scope, greedy single-link clusters each scope (members pre-sorted by `compareDedupWinner`, so the survivor matches what the guard would pick), and — **only with `apply: true`** — calls `collapseDuplicateClaims`. Dry run by default, like `migrate-v3.ts`. `formatDedupSweep` renders the Slack/CLI summary.
- `src/memory/factory.ts` — `createMemoryStore(dbPath = "data/memory.db", options?)` → `SqliteMemoryStore`; `options.dedupThreshold` comes from `config.memory.dedupThreshold` at boot, else `MEMORY_DEDUP_THRESHOLD`.
- `src/memory/ingestion.ts` — `MemoryIngestor`: hot-path capture. `captureSlackMessage` / `captureRunnerResult` / `captureRoutingDecision` / `captureRunnerEvents` write **only** `appendSourceRecord` (raw provenance — not recallable). Plus `sourceIdFor`/`slug` helpers.
- `src/memory/cli.ts` — `runMemoryCli`: commands `consolidate-v3` (runs `runConsolidationSweep`), `recall-claims` (`--query` embeds in-process; inspection — `recordUsage:false`), `add-claim` (embeds via the provider when `--embedding` is omitted; lesson claims also receive all three retrieval variants, while explicit lesson vectors must use `add-lesson` unless `--skip-dedup` explicitly requests a verbatim restore), `add-lesson`, `add-fact` (the `add-*` commands **mirror** into the claim store via `mirrorClaim` so new lessons/facts are immediately recallable; the mirror reports `claimAction`/`claimId` so a merge is visible), and `dedup-sweep [--threshold n] [--apply]` (dry run without `--apply`).
- `src/memory/retrieval-text.ts` — deterministic lesson/fact retrieval projections; lesson projections include `applies_when`.
- `src/memory/reembed-retrieval.ts` — recoverable corpus backfill (`bun run memory:reembed`): exports JSONL, optionally rewrites projections in validated Cursor Composer batches, and checkpoints every complete batch. Resume requires matching model + prompt-recipe metadata, then reuses only rows whose tool-owned source hash still matches; incompatible, stale, or new rows are regenerated without discarding unrelated valid model work. Composer returns only ids + retrieval text; source hashes are bound locally. Projections target ≤2,000 chars, with a source-length exception capped at 2,500 for dense rules. The command dry-runs by default, creates an SQLite backup before `--apply`, then locally re-embeds every active claim without changing authoritative text. `--missing-lesson-variants` is the narrower repair path: it backs up first, fills only absent or stale lesson variants 1/2 in bounded embedding batches, derives title/body from authoritative `claim.text` (using legacy `applies_when` only while the legacy title/body still match), works without a legacy `lesson` row, aborts if authoritative source changes during embedding, and is idempotent.
- `src/memory/migrate-v3.ts` — One-shot, committed, dry-run-by-default migration: legacy `lesson`+`memory_fact` → embedded `claim` (proximity-dedup), then `dropCondemned`-gated DROP of `memory_event`/`edge`/`mention`/`memory_search_doc`/`candidate_rule`/`memory_fts`. Cutover is complete. Writes with `skipDedup: true` — it has already clustered, and historical rows (including archived ones) must go in verbatim.

### Embeddings (`src/memory/embedding/`)
- `local.ts` — `LocalEmbeddingProvider`: in-process `onnx-community/harrier-oss-v1-270m-ONNX` (640-dim, q8) via `@huggingface/transformers`. Last-token pooling (reads the model's `sentence_embedding` output), query-vs-document prompt templates, one text per forward pass (no padded batches).
- `hashing.ts` — `HashingEmbeddingProvider`: deterministic zero-dependency stub for tests/dev.
- `factory.ts` — `createEmbeddingProvider("local" | "hashing")`.
- `types.ts` — `EmbeddingProvider` / `EmbedMode` ("query" | "document").

### Profiles (`src/memory/profiles/`) — keyed, markdown, not embedded
- `store.ts` — `ProfileStore`: files at `<root>/<people|repos|projects|situations>/<slug>.md`; `upsertProfile` (keyed merge by `entity_ref`, unions evidence, bumps `updated_at`), `fetchByEntityRef` (single keyed read; bumps `last_used_at` only when `recordUsage:true`), `list`. Person profiles carry `slack_user_id` so display-name changes do not fork identity. Profile↔markdown mapping + field specs per kind.
- `types.ts` — `ProfileKind` (person/repo/project/situation), `Profile`/`ProfileBase`/`ProfileInput`, `ProfileFetchOptions`.
- `frontmatter.ts` — `parseDocument`/`serializeDocument` (frontmatter + prose body).
- `factory.ts` — `createProfileStore`. `index.ts` — barrel.

### Consolidation engine (`src/memory/consolidation/`) — offline LLM write path
- `consolidate.ts` — `consolidateSession`: uses a pre-fetched `records` set when given (else reads unconsolidated records by `threadId`/`limit`), builds context (existing profiles — keyed refs first, then the rest of the corpus via `ProfileStore.list()` newest-first up to `PROFILE_CONTEXT_CAP = 20` — plus nearby claims and the resolved identity map from optional `resolvePeople`), calls the injected LLM (forwarding `bodyCap` to the prompt), persists **episodes → profiles → claims** (cosine proximity-dedup at `DEFAULT_DEDUP_THRESHOLD = 0.92`, bucketed by `dedupScopeKey` for both the existing-claim pre-check and the in-batch check — an unscoped pre-check DROPS a repo-scoped draft that merely sits near a global claim, and a drop is strictly worse than the store's merge), stamps records consolidated. Local `cosine` + `fnv1a` (stable 64-bit claim id) helpers.
- `identity.ts` — `referencedSlackUserIds` (batch's `actor_id`s + `<@U…>` mentions), `PeopleResolver` (id → display name; unresolved ids omitted), `createSlackPeopleResolver` (production: `users.info` via the shared `resolveUserName` cache). Evidence names people only as raw Slack ids, so without this the model can't attribute anything to a person profile.
- `persona.ts` — `runPersonaConsolidationSweep`: before thread records are stamped, finds active human actors, resolves stable Slack identity, reads a rolling 80-message history across threads (including already-consumed raw evidence), and creates/updates one grounded person profile. A three-message floor avoids a model call for one-off chatter; the prompt prohibits sensitive inference and transactional-request profiling.
- `subjects.ts` — `runSubjectConsolidationSweep`: builds repo profiles from cumulative source evidence (normalizing known `.worktrees` container aliases) and situation profiles from a rolling cross-thread human Slack window. Daily runs consider active subjects; `--subjects-all` / `--profiles-all` rebuild historical subjects.
- `sweep.ts` — `runConsolidationSweep`: the shared orchestration loop. Full-sweep mode first runs the cumulative persona phase, then filters/groups unconsolidated records (`DEFAULT_CONSOLIDATION_KINDS` = `slack_message`/`curated_fact`/`manual_correction`), splits oversized thread groups and First-Fit-Decreasing bin-packs the rest. Each batch is isolated on failure. `threadId` mode keeps the single-thread `limit` path. Summary entries expose both persona updates and normal derivation totals. Used by the CLI, workflow, and MCP tool.
- `runner.ts` — `createRunnerInvoke`: production `ConsolidationInvoke`. `runner: "claude" | "opencode" | "codex"` (default `opencode`) selects the one-shot subprocess (injectable `runText`) and applies the same untrusted-content boundary to every provider: neutral `os.tmpdir()` cwd, no usable tools/MCP authority, and no project/user hooks. Claude uses `--safe-mode --tools "" --strict-mcp-config --settings '{"disableAllHooks":true}' --no-session-persistence` and stdin; OpenCode uses `--pure`, disables default plugins and `.claude` discovery, forces the inline `junior-consolidation-isolated` no-tools/no-permission agent, deletes shell config overrides, and executes beneath a fresh HOME/XDG config/data/cache/state root so global user config cannot merge. It provisions only the original OpenCode `auth.json` into the sterile data root at `0600` (no settings, agents, plugins, or instructions); a missing explicit credential may fail over to environment auth, while a malformed auth path fails closed. `withIsolatedOpenCodeRuntime` owns setup and cleanup around process creation, so the root is removed even if `Bun.spawn` throws synchronously. Its documented `run` prompt remains a positional after `--`; the live hostile-config test validates that the resolved OpenCode configuration excludes a synthetic user MCP and instruction. Codex uses `--ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -s read-only --color never` and stdin with a unique `-o` temp output file (deleted after). The model is ALWAYS pinned — `DEFAULT_OPENCODE_MODEL = opencode-go/deepseek-v4-pro`, `DEFAULT_CLAUDE_MODEL = claude-opus-5` (a VALID id; `sanitizeClaudeModel` defensively strips a trailing `[…]` tag like junior's `[1M]` notation), `DEFAULT_CODEX_MODEL = gpt-5.6-sol` with `effort` default `low` (`-c model_reasoning_effort="…"`). Output is parsed/validated against `consolidationOutputSchema`; 5-min timeout guard SIGINTs the process tree.
- `prompt.ts` — `buildConsolidationPrompt(records, context, bodyCap?)`: encodes the HIGH BAR (default output is empty) + shows existing profiles/claims to avoid restating (profile bodies near-whole, 1500-char guard, because an emitted body REPLACES the file's) and a "Who is who" Slack-id → name section (from `context.people`; `from=` lines are name-annotated; reuse a shown profile's exact `entity_ref`, never a second slug); notes records may span multiple `thread=` groups (judge each on its own). With `bodyCap` set it truncates ONLY `BODY_CAPPED_KINDS` (`runner_output`/`routing_decision`) bodies (`…[truncated]`); high-value kinds go in whole. `cappedBodyLength()` is the shared sizing helper the sweep uses so packing matches what is sent.
- `types.ts` — `EpisodeDraft`/`ProfileDraft`/`ClaimDraft`, `ConsolidationOutput`/`ConsolidationInvoke`, `ConsolidationReport`, and `consolidationOutputSchema` (JSON Schema). `index.ts` — barrel.

## Integration points (outside `src/memory/`)
- `src/index.ts` — builds the store + `MemoryIngestor` on boot, injects the ingestor into the session manager.
- `src/session/manager.ts` — hot path: `captureSlackMessage` on incoming messages, `captureRunnerResult` on runner completion.
- `src/mcp/slack-server.ts` — MCP tools `memory_recall` (`recallMemory`: keyed profiles + hybrid recall, cosine 0.55 or lexical 0.75 eligibility, source-section expansion, usage accounting, unioned claim-kind + fact-subtype scopes, optional procedure quota), `memory_add` (`addMemory`: embed + store one claim with optional source provenance), `memory_feedback` (`recordMemoryFeedback`: explicit useful/useless judgment that increments counters for known claim ids), and `memory_consolidate` (`runConsolidationSweep`). Lazy embedder/profile-store seams; `withMemoryStore` opens/closes per call.
- `src/workflows/executor.ts` — the `memory-consolidation` workflow runs `runConsolidationSweep` (sweep IS the LLM pass); the `memory-dedup-sweep` workflow runs `runDedupSweep` natively in REPORT-ONLY mode (deterministic, so no runner; applying stays an explicit operator CLI action).
- `src/config.ts` — `config.memory.dedupThreshold` (`MEMORY_DEDUP_THRESHOLD`, default 0.92), passed into the store at boot from `src/index.ts`.
- `src/http/routes/memory.ts` — dashboard: `handleMemoryRecall` (embeds query at the boundary, `recordUsage:false`), `handleMemoryProjection` (`exportClaimVectors` → `projectClaims`), plus `/api/memory` docs browsing.
- `src/http/projection.ts` — `projectClaims`: PCA-to-2D + KNN edges for the "memory cloud" debug view (computed at render time, nothing stored).

- Fixtures that need a vector-less or deliberately near-identical claim row seed it with `skipDedup: true` — that flag is the only way past the write guard, and using it marks the fixture as synthetic rather than a production write path.
